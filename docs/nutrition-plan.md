# 設計・実装計画: 栄養成分の表示(日本食品標準成分表から計算)

担当: 設計 + 実装 + レシピ + 運用。ブランチは `main` に揃えた `claude/ai-recipe-auto-posting-xzbctl`。

## Context
レシピ検索では「カロリー」が頻繁に求められる。AI が数値を推定するとずれて信用を損なうため、**文部科学省『日本食品標準成分表(八訂)増補2023年』の公式データから、スクリプトで計算する**(ユーザー確認済み)。表示項目は基本5項目(エネルギー・たんぱく質・脂質・炭水化物・食塩相当量)、1人分あたり。

## 前提と制約(調査結果)
- データは自由に利用できる。許諾手続きは不要だが、「日本食品標準成分表(八訂)増補2023年から引用(または出典)」の明記が必要。
- **この環境は www.mext.go.jp に接続できない**(ネットワークポリシーで拒否。確認済み)。そのため、数値を記憶で作ることは絶対にしない。ユーザーが、環境の許可ドメインに `www.mext.go.jp` を追加する(セッションのタイトルバーの環境メニュー → Edit → Network access)。追加後、新しいセッションが必要になる可能性がある。
- 自動投稿の Routine は、リポジトリ内のデータだけを使うので、MEXT への接続は不要。
- 公式Excelの正確なダウンロードURLは、接続できるようになってから公式ページ(`https://www.mext.go.jp/a_menu/syokuhinseibun/mext_00001.html`)で確認する。**データが取得できなければ、この計画は中断して相談する**(代替: GitHub Actions で取得)。

## 設計
### 1. データ(公式の全食品を取り込む)
- `scripts/build-food-data.mjs`(`npm run food:build -- <Excelのパス>`): 公式Excel(本表)を読み、**全食品**(約2,500件)について、食品番号・食品名・廃棄率・100gあたりの次の値を `data/food-composition.json` に書き出す: エネルギー(kcal)、たんぱく質、脂質、炭水化物、食塩相当量。`Tr`(微量)は0、`-`(未測定)は null、括弧つき(推定値)は数値として扱う。メタ情報(出典名、版、取得日)も入れる。Excel本体はコミットしない(サイズ・著作の扱いのため)。
- 全食品を入れる理由: 自動投稿が新しい食材を使っても、データを増やすために公式サイトへ接続する必要がない。
- `npm run food -- <キーワード>`: 食品名を検索して、候補(食品番号・食品名・100gあたりの値)を表示する(レシピ担当・自動投稿が、材料に対応する食品を選ぶのに使う)。
- 読み取りには `exceljs`(devDependency、ビルド用スクリプトのみ)。
- 自動検証: 全食品で「エネルギー ≒ たんぱく質×4 + 脂質×9 + 炭水化物×4」の大まかな整合(列の読み違いを検出)、値が数値、食品番号の重複なし。

### 2. レシピのデータ
- スキーマの `ingredients` の各要素に、`food`(食品番号、文字列)と `grams`(可食部の重さ g、数値)を追加。`name` と `amount`(表示用)は、そのまま残す。
- 重さは**可食部**(皮・種・骨などを除いた量)で書く。成分表は可食部100gあたりの値のため、廃棄率は計算に使わない(重さの書き方のルールとして、手順書に明記)。
- 水など、成分がない材料は、成分表の「水」(または該当食品)を使う。

### 3. 計算(`src/lib/nutrition.mjs`、Astro とスクリプトで共用)
- `nutritionPerServing(recipe, foods)`: 全材料の `grams × 100gあたりの値 / 100` を合計して、`servings` で割る。表示の丸めは、エネルギー整数、他は小数1桁。
- 一部の材料にだけ `food`/`grams` がある場合は計算しない(検証でエラーにする)。

### 4. 表示
- レシピ詳細: 「栄養成分(1人分・目安)」の表(5項目)と注記「日本食品標準成分表(八訂)増補2023年をもとに計算した目安です。調理による重量・成分の変化、食材ごとの差は考慮していません。」。出典(文部科学省)を明記。
- 一覧のカード: 「約◯kcal/人分」を、調理時間の行に追加。
- JSON-LD(Recipe)に `nutrition`(`calories`、`proteinContent`、`fatContent`、`carbohydrateContent`)を追加。食塩相当量はナトリウムと異なるため入れない。
- `about` に、栄養成分の説明と出典。健康・減量の効果は断定しない(既存ルールを維持)。

### 5. 検証(`scripts/validate-recipes.mjs`)
- `food` が `data/food-composition.json` に存在する、`grams` が正の数、全材料に `food`/`grams` がある(無ければエラー。全レシピのバックフィル後に必須化)。
- `amount` が「◯g」の場合、`grams` と一致(「約」つきは±10%)。大さじ・小さじの場合、`grams` が、体積(15ml/5ml × 数量)に対して0.4〜1.8倍の範囲か(外れたら警告)。
- 1人分のエネルギーが 20〜1,200 kcal の範囲外なら警告。
- テスト: 計算(丸め・分割)、検証の各ケース、データ整合(列の読み違い検出)。

### 6. 既存12レシピのバックフィル
- 各材料に `food` と `grams` を設定する。**PRの説明に、材料 → 食品名 → 重さ → 1人分の値の一覧を載せ**、ユーザーが妥当性を確認できるようにする。計算結果のエネルギーは、一般的な目安(例: 鶏の照り焼き 1人分で数百kcal台)と比べて、極端な値がないか確認する。

### 7. 自動投稿・ドキュメント
- `docs/auto-post.md`: 材料ごとに `npm run food -- <名前>` で食品を選び、`food` と `grams`(可食部)を書く手順を追加。PRの説明に、1人分の栄養成分を載せる。
- `agents/recipe/AGENTS.md`、`CLAUDE.md`(コマンド・データ・出典)、`docs/design.md`、`about`。
