# 自動投稿の手順書

2日に1回、新しいレシピを1つ作って PR を出す。スケジュール実行(Routine)が毎日 6:07(日本時間)に起動し、このファイルの手順に従う。
無人実行なので、質問はせず、判断して進める。**フェーズ1: マージはユーザーがスマホで行う。自分ではマージしない。**

## 守ること(最重要)

- 1回の実行で作るレシピは **1つだけ**。
- **マージしない。** `scripts/`・`.github/`・`src/pages/`・`src/layouts/`・`src/lib/`・`src/content.config.ts`・`data/` は変更しない。
- 画像は作らない(画像は GitHub Actions が生成する)。`OPENAI_API_KEY` は使わない・出力しない。
- ルールは `CLAUDE.md`、`agents/recipe/AGENTS.md`、`agents/ops/AGENTS.md` に従う。文章はすべて日本語。
- 他サイトの文章・レシピを転載しない。誇大表現・医療的な効能の断定をしない。

## 手順

### 1. 準備と現状確認
1. リポジトリを `main` の最新にする(`git fetch origin main` と `git checkout main` と `git reset --hard origin/main` に相当。未コミットの変更がない前提)。
2. `npm ci` を実行する。
3. `npm run recipe:status` を実行し、今日の日付(JST)、最新レシピの日付と経過日数、既存レシピ、タグ別件数、季節の目安を確認する。

### 2. 実行してよいか判定
- 未マージの `recipe/**` ブランチの PR を GitHub で確認する(`list_pull_requests` で open、head が `recipe/` で始まるもの)。
- 次のどれかに当てはまる → 何もせず終了する(通知しない)。
  - `recipe:status` の「最新から2日以上たっている」が「いいえ」(`main` のレシピが2日以内)
  - 未マージのレシピ PR のうち、**作成から2日未満**のものがある(前回の投稿がまだ新しい)
- 未マージのレシピ PR が **2件以上** → 新しく作らない。「未マージのレシピ PR が N 件あります」とスマホに通知して終了する。

### 3. 題材を選ぶ
1. `docs/recipe-ideas.md` の「リスト」に、取り消し線でない料理があれば、先頭を採用する。
2. 無ければ、次の条件で1つ選ぶ。
   - 既存レシピと、料理名・主材料・調理法が重ならない
   - タグ別件数が少ないジャンル(主菜・副菜・汁物・丼・麺・卵料理・魚・野菜など)を優先する
   - 季節の目安に合う(旬の食材など)
   - 家庭で再現しやすく、材料が手に入りやすい和食を中心にする(洋食・中華・デザートも可)

### 4. レシピを書く
- `src/content/recipes/<slug>.md` を作る。書式は既存のレシピ(例: `nikujaga.md`)と同じにする。
  - `slug` は小文字のローマ字とハイフン。`publishedAt` は今日(JST)。
  - `servings` は2人分が基本。材料は分量つき。手順は4〜6工程。
  - `allergens` は特定原材料7品目(えび・かに・小麦・そば・卵・乳・落花生)のうち使うものだけ。
  - `aiGenerated: true`、`image.aiGenerated: true`。`image.src` は `/images/recipes/<slug>.webp`。`image.alt` を書く。
  - `image.prompt` に、完成した料理の見た目を具体的に書く(器・盛り付け・彩り。ブランド・人物・文字は入れない)。
- 栄養成分(必須): 材料ごとに、成分表の食品番号 `food` と、可食部の重さ `grams`(g)を書く。栄養成分は、サイトがこの2つから計算する(**数値をレシピに書かない・推定しない**)。
  - 例: `- { name: "玉ねぎ", amount: "1/2個", food: "06153", grams: 100 }`
  - 食品は `npm run food -- <キーワード>` で探す(例: `npm run food -- たまねぎ 生`、`npm run food -- にわとり もも 皮つき`)。生の材料は「生」、調味料は一般的なもの(しょうゆ=こいくちしょうゆ 17007、砂糖=上白糖 03003、みりん=本みりん 16025、酒=清酒 普通酒 16001、サラダ油=調合油 14006、だし=かつお・昆布だし 17021、みそ=米みそ 淡色辛みそ 17045)を選ぶ。
  - `grams` は**可食部**(皮・種・骨などを除いた量)。重さの目安: 大さじ1 = しょうゆ・みりん・みそ 18g、酒 15g、砂糖 9g、油 12g、ごま 6g、片栗粉 9g(小さじはその1/3)。卵1個 = 50g。少々 = 0.5g、ひとつまみ = 1g。だし・水は 1ml = 1g。
  - 水・氷と、捨てる材料(ゆで湯の塩、揚げ油の残りなど)は `food: "-"` とし、`grams` を書かない(計算に含めない)。成分がある調味料などには使わない。
  - `amount` が「◯g」「約◯g」のときは、`grams` をそれに合わせる(購入時の重さなら、廃棄率を引いた可食部でもよい)。
- 買い物リンク(任意): 手順に出てくる**道具や、特別な材料**があるときだけ、`shopping` に **0〜3件**、`label`(表示名)と `keyword`(楽天・Amazon の検索キーワード)を書く。
  - 例: `shopping: [{ label: "落とし蓋", keyword: "落とし蓋 ステンレス" }]`
  - 日常的な材料(しょうゆ、卵、玉ねぎなど)には付けない。URL、商品名、価格、効果の断言は書かない。リンクはサイトが自動で作る(IDが設定されているサービスだけ表示される)。
- 安全面: 肉・魚・卵は中心まで火を通す旨を手順かコツに書く。しょうゆ・みそ・ごまなどは、必要に応じて原材料表示の確認を促す。
- `docs/recipe-ideas.md` から採用した場合は、その行を取り消し線にする。

### 5. 検証
- `npm run validate`: **エラーは「画像ファイルが見つかりません(生成待ち)」の1件だけ**が正常。それ以外のエラー・警告が出たら、レシピを直して再実行する(修正は2回まで)。ただし、捨てる材料(ゆで湯の塩など)に `food: "-"` を使ったときの警告は、そのままでよい(PR本文に理由を書く)。
- 1人分の栄養成分を確認する(`npm run build` 後、`dist/recipes/<slug>/index.html` の「栄養成分」の表)。一般的な目安(主菜で数百kcal、汁物で百kcal前後など)から極端に外れていたら、食品番号と重さを見直す。
- `npm test` と `npm run build` が成功すること。
- 直せないときは、ブランチを push せずに中止し、失敗の理由をスマホに通知して終了する。

### 6. ブランチを push する
- 最新の `main` から `recipe/<slug>` を作り、レシピ(と、採用した場合は `docs/recipe-ideas.md`)をコミットして push する。
  - コミットメッセージ例: `レシピを追加: <料理名>`
- push すると、GitHub Actions(`画像生成`)が画像を作って同じブランチにコミットし、CI を再実行する。

### 7. PR を作る
- ベースは `main`、ヘッドは `recipe/<slug>`。
- タイトル: `レシピを追加: <料理名>`
- 本文に次を書く。
  - 概要(料理の説明、選んだ理由: 季節・ジャンルのバランス)
  - アレルゲン表示
  - 栄養成分(1人分)と、材料の対応の一覧(材料 → 食品番号・食品名 → 重さ。`"-"` は「計算に含めない」と理由)
  - 安全面の確認(加熱など)
  - 注意: 「画像は GitHub Actions が追加します。最初の CI は画像が無いため赤になり、画像のコミット後に再実行されて緑になります。」
  - マージするとサイトに公開される旨(スマホで Vercel のプレビューを確認してからマージ)
- **マージしない。**

### 8. 通知する
- `PushNotification`(`status="proactive"`)で、200文字以内に次を送る。
  - 成功: 「新しいレシピのPRができました: <料理名> #<PR番号>。画像は数分で追加されます。」
  - 中止: 理由を一言で。

## 困ったとき
- push や PR 作成ができない(権限・ネットワーク)場合は、無理に別の方法を探さず、状況をスマホに通知して終了する。
- 判断に迷う内容(安全面が不確か、重複しそう)は、そのレシピを作らず、別の題材にする。

## フェーズ2について
検証に通ったものを自動マージする運用は、ユーザーの明示的な指示があるまで行わない。
